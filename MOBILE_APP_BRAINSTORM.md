# Mobile App Brainstorm: TickTick Link Saver

## Problem

Chrome extension only works on desktop. Need the same "share URL → TickTick task" flow on phones, for both Android and iOS eventually.

## Decision: Capacitor

JS-based, reuses existing code, cross-platform (Android + iOS from one codebase). The app is simple enough that WebView perf is a non-issue.

---

## Repo Structure: Two Options

### Option A: Monorepo (Recommended)

Rename this repo to `ticktick` (or keep it as `ticktick-extension`) and reorganize:

```
ticktick/
├── extension/                    # Chrome extension
│   ├── manifest.json
│   ├── background.js
│   ├── popup.html
│   ├── popup.js
│   ├── popup.css
│   ├── content.js
│   ├── config.js                 # gitignored, real credentials
│   ├── config.js.sample
│   └── icons/
│
├── app/                          # Capacitor mobile app
│   ├── www/                      # Web layer (served by Capacitor)
│   │   ├── index.html
│   │   ├── app.js
│   │   ├── app.css
│   │   └── config.js             # gitignored, real credentials
│   ├── config.js.sample
│   ├── capacitor.config.ts
│   ├── package.json
│   ├── android/                   # auto-generated by Capacitor
│   └── ios/                       # auto-generated by Capacitor
│
├── shared/                        # Code used by both extension and app
│   ├── api.js                     # apiGet(), apiPost()
│   ├── resolve.js                 # resolveUrl(), decodeEntities(), fetchPageTitle()
│   └── README.md                  # How shared code is consumed
│
├── .gitignore
├── CLAUDE.md
└── README.md
```

**How shared/ is consumed (no build tool needed):**

- **Extension:** `<script src="../shared/api.js">` in popup.html, `importScripts("../shared/api.js")` in background.js. Or just copy the files at dev time — they're tiny.
- **App:** Same — `<script src="../../shared/api.js">` in index.html. Or a simple copy script in package.json: `"prebuild": "cp ../../shared/*.js www/"`.

Actually, the simplest approach: **don't overthink the sharing mechanism.** The shared code is ~60 lines total. Both sides can just import the files directly, or you copy-paste and move on. If they drift apart slightly (mobile adds error retry logic, extension doesn't), that's fine.

**Pros:**
- One repo, one place to look
- Easy to keep shared logic in sync
- Single CLAUDE.md, single set of issues/PRs
- `git log` shows the full picture

**Cons:**
- Extension dev path changes slightly (load `extension/` folder at chrome://extensions instead of repo root)
- Mixed git history (extension commits and app commits interleaved)

### Option B: Separate Repos

```
ticktick-extension/               # This repo, stays exactly as-is
├── background.js
├── popup.html / popup.js / popup.css
├── content.js
├── config.js / config.js.sample
├── manifest.json
└── icons/

ticktick-app/                     # New repo
├── www/
│   ├── index.html
│   ├── app.js                    # Has its own copy of API helpers + resolveUrl
│   ├── app.css
│   └── config.js
├── config.js.sample
├── capacitor.config.ts
├── package.json
├── android/
└── ios/
```

**Pros:**
- Extension workflow is unchanged — repo root IS the extension, no subfolder
- Clean separation, independent versioning
- App can evolve independently (different release cadence, different CI)

**Cons:**
- Shared code is duplicated (api helpers, resolve logic)
- Two repos to maintain, two sets of issues
- If you fix a bug in resolveUrl(), you fix it in two places

---

### Verdict

**Go with Option A (monorepo)** unless the extension subfolder thing really bothers you. Reasons:

1. The shared code is small but important — `resolveUrl()` has real logic (redirect following, og:title parsing, entity decoding) that you don't want diverging
2. You're a solo developer — monorepo overhead is zero, separate-repo overhead is real (switching repos, remembering to sync fixes)
3. The extension subfolder change is a one-time thing: update `chrome://extensions` to point at `extension/` instead of repo root, done

## What Shared Code Looks Like

### shared/api.js

Extracted from popup.js — the API helpers that both platforms use identically:

```js
const API_BASE = "https://api.ticktick.com/open/v1";

async function apiGet(path, token) {
  const res = await fetch(API_BASE + path, {
    headers: { Authorization: `Bearer ${token}` },
  });
  if (!res.ok) throw new Error(`API error: ${res.status}`);
  return res.json();
}

async function apiPost(path, body, token) {
  const res = await fetch(API_BASE + path, {
    method: "POST",
    headers: {
      Authorization: `Bearer ${token}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(body),
  });
  if (!res.ok) throw new Error(`API error: ${res.status}`);
  return res.json();
}
```

Note: token is now a parameter instead of a module-level variable — both platforms pass it in from their own storage.

### shared/resolve.js

Extracted from background.js — title fetching logic the mobile app needs:

```js
function decodeEntities(str) {
  return str
    .replace(/&amp;/g, "&").replace(/&lt;/g, "<").replace(/&gt;/g, ">")
    .replace(/&#0?39;/g, "'").replace(/&quot;/g, '"')
    .replace(/&#x27;/g, "'").replace(/&#x2F;/g, "/")
    .replace(/\s+/g, " ").trim();
}

async function resolveUrl(url) {
  try {
    const res = await fetch(url, { redirect: "follow" });
    const finalUrl = res.url;
    let title = null;

    const contentType = res.headers.get("content-type") || "";
    if (contentType.includes("text/html")) {
      const html = await res.text();
      const titleMatch = html.match(/<title[^>]*>([\s\S]*?)<\/title>/i);
      if (titleMatch) {
        const decoded = decodeEntities(titleMatch[1]);
        if (decoded && decoded !== finalUrl) title = decoded;
      }
      if (!title) {
        const ogMatch = html.match(/<meta[^>]+(?:property|name)=["']og:title["'][^>]+content=["']([^"']*?)["']/i)
          || html.match(/<meta[^>]+content=["']([^"']*?)["'][^>]+(?:property|name)=["']og:title["']/i);
        if (ogMatch) title = decodeEntities(ogMatch[1]);
      }
      if (!title) {
        const twMatch = html.match(/<meta[^>]+(?:property|name)=["']twitter:title["'][^>]+content=["']([^"']*?)["']/i)
          || html.match(/<meta[^>]+content=["']([^"']*?)["'][^>]+(?:property|name)=["']twitter:title["']/i);
        if (twMatch) title = decodeEntities(twMatch[1]);
      }
    }
    return { url: finalUrl, title: title || finalUrl };
  } catch {
    return { url, title: url };
  }
}
```

## Mobile App: Platform Swap Details

Your popup.js has 4 Chrome-specific things. Everything else (views, feedback, project picker) stays as-is:

### 1. Storage: `chrome.storage.local` → Capacitor Preferences

```js
// EXTENSION
await chrome.storage.local.get(["access_token", "project_id", "project_name"]);
await chrome.storage.local.set({ project_id: id, project_name: name });

// APP
import { Preferences } from '@capacitor/preferences';
const { value } = await Preferences.get({ key: 'access_token' });
await Preferences.set({ key: 'project_id', value: id });
```

### 2. Get URL: `chrome.tabs.query()` → Share Intent

```js
// EXTENSION
const [tab] = await chrome.tabs.query({ active: true, currentWindow: true });

// APP — receive from share sheet
import { SendIntent } from 'send-intent';
const intent = await SendIntent.checkSendIntentReceived();
if (intent?.url) {
  const resolved = await resolveUrl(intent.url);  // reuse shared/resolve.js
  pageTitle.textContent = resolved.title;
  pageUrl.textContent = resolved.url;
}
```

### 3. OAuth: `chrome.identity` → In-App Browser

```js
// EXTENSION
chrome.runtime.sendMessage({ action: "authenticate" });
// background.js handles via chrome.identity.launchWebAuthFlow()

// APP — open OAuth in system browser, catch redirect
import { Browser } from '@capacitor/browser';
import { App } from '@capacitor/app';

async function authenticate() {
  const state = crypto.randomUUID();
  const authUrl = `https://ticktick.com/oauth/authorize?` +
    `client_id=${CLIENT_ID}` +
    `&redirect_uri=${encodeURIComponent(REDIRECT_URI)}` +
    `&response_type=code&scope=tasks:write tasks:read` +
    `&state=${state}`;
  await Browser.open({ url: authUrl });
}

// Catch the redirect
App.addListener('appUrlOpen', async ({ url }) => {
  if (!url.startsWith(REDIRECT_URI)) return;
  const code = new URL(url).searchParams.get('code');
  await exchangeCodeForToken(code);  // same POST as background.js:168-180
});
```

### 4. Token Exchange: Moves from background.js into app.js

```js
async function exchangeCodeForToken(code) {
  const res = await fetch("https://ticktick.com/oauth/token", {
    method: "POST",
    headers: {
      "Content-Type": "application/x-www-form-urlencoded",
      Authorization: "Basic " + btoa(CLIENT_ID + ":" + CLIENT_SECRET),
    },
    body: new URLSearchParams({
      code,
      grant_type: "authorization_code",
      scope: "tasks:write tasks:read",
      redirect_uri: REDIRECT_URI,
    }),
  });
  const data = await res.json();
  await Preferences.set({ key: 'access_token', value: data.access_token });
}
```

### 5. Everything Else: No Changes

`showView()`, `showFeedback()`, `showProjectPicker()`, project select event listeners, add task button handler — all vanilla JS DOM manipulation, works identically in a WebView.

## Mobile App UI

The extension popup is 320px wide, designed for a dropdown. The mobile app needs a full-screen layout but the UI is essentially the same three views. Changes:

```css
/* Extension: fixed width popup */
body { width: 320px; padding: 16px; }

/* App: full-screen mobile */
body {
  width: 100%;
  min-height: 100vh;          /* fill the screen */
  padding: 24px 20px;
  font-size: 16px;            /* bigger touch targets */
}

.btn { padding: 14px 20px; font-size: 16px; }  /* bigger buttons */
select { padding: 14px; font-size: 16px; }

/* When opened via share (not direct launch), show a compact card-style UI */
/* so it feels like a quick action, not a full app */
body.share-mode {
  display: flex;
  flex-direction: column;
  justify-content: center;
}
```

Plus a new "empty state" for when the app is opened directly (not via share):

```html
<div id="view-empty" class="view" hidden>
```

## Setup Steps

```bash
# 1. Reorganize this repo
mkdir extension
git mv background.js content.js popup.html popup.js popup.css manifest.json icons config.js.sample extension/
# (move config.js manually since it's gitignored)

mkdir shared
# Create shared/api.js and shared/resolve.js (extracted from popup.js and background.js)
# Update extension/popup.html to reference ../shared/api.js
# Update extension/background.js to importScripts("../shared/resolve.js", "../shared/api.js")

# 2. Scaffold the app
mkdir -p app/www
cd app
npm init -y
npm install @capacitor/core @capacitor/cli @capacitor/preferences @capacitor/browser @capacitor/app
npm install send-intent
npx cap init "TickTick Saver" com.yourname.tickticksaver --web-dir=www

# 3. Create app web code in app/www/
# index.html — adapted from extension/popup.html (full-screen, share-mode)
# app.js — adapted from extension/popup.js (Capacitor APIs)
# app.css — adapted from extension/popup.css (mobile sizing)
# Copy config.js into app/www/

# 4. Add platforms
npx cap add android
# npx cap add ios   (when ready)

# 5. Configure Android share intent
# Edit app/android/app/src/main/AndroidManifest.xml

# 6. Build
npx cap sync
npx cap open android   # → Android Studio → Build APK
```

## Android Share Intent Config

In `app/android/app/src/main/AndroidManifest.xml`, add to the main activity:

```xml
<intent-filter>
    <action android:name="android.intent.action.SEND" />
    <category android:name="android.intent.category.DEFAULT" />
    <data android:mimeType="text/plain" />
</intent-filter>
```

## OAuth Redirect URI for Mobile

Register a new redirect URI at https://developer.ticktick.com/manage:
- `com.yourname.tickticksaver://oauth/callback`

Capacitor catches custom scheme URLs natively via the `appUrlOpen` event.

```
EXTENSION (unchanged):

APP — FIRST TIME:
  Open app → "Connect to TickTick" → OAuth in browser → redirect back →
  Pick project → See "Share a link to get started" empty state
```
